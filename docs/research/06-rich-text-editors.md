# 06 — Rich-text editors for a no-build, CDN-loaded browser Admin

Research ticket: GitHub issue #6 ("Research: Rich-text editor options for a no-build browser Admin").
Date of research: 2026-10-05. Versions and dates below were read from the npm registry on that day; licence and feature facts from each project's GitHub repository or official docs (URLs cited inline).

> Verification caveat: this research sandbox blocks outbound requests to `esm.sh`, `cdn.jsdelivr.net`, `unpkg.com`, `bundlephobia.com` and most vendor sites (tiptap.dev, quilljs.com, ckeditor.com, tiny.cloud, lexical.dev, milkdown.dev). The "loads from CDN" column is therefore based on each project's **official documentation and open GitHub issues**, not on a live download. Bundle sizes are npm `unpackedSize` (verified) plus an approximate gzip figure marked "≈" from memory. Both must be confirmed with a 5-minute browser test before Stage 6 code is written — see Open questions.

## 1. สรุปภาษาไทยแบบง่าย (10 บรรทัด)

1. เราต้องการ "กล่องพิมพ์บทความ" ที่ใช้งานเหมือน Word อยู่ในหน้า Admin ที่เป็นไฟล์ HTML ธรรมดา โหลดจาก CDN ไม่ต้องมีเครื่องมือ build และไม่มีเซิร์ฟเวอร์
2. ตัวเลือกที่แนะนำอันดับ 1 คือ **Tiptap** (สร้างบน ProseMirror) — ฟรี MIT, เอกสารทางการสอนโหลดจาก jsDelivr ได้ตรง ๆ, ออก HTML สะอาด, จำกัดปุ่ม/หัวข้อได้ตามแบรนด์, มีส่วนขยายรูป ตาราง YouTube โค้ด และ "กล่องหมายเหตุ" ทำเองได้
3. อันดับ 2 คือ **Editor.js** — ฟรี Apache-2.0, เป็นแบบ "บล็อก" ตั้งแต่ต้น, ออกเป็น JSON แล้วเราแปลงเป็น HTML เอง จึงคุมหน้าตาได้ 100% แต่หน้าตาตอนพิมพ์ไม่เหมือน Word เท่า Tiptap
4. อันดับ 3 คือ **Trix** (จากทีม Basecamp/Rails) — เบา ฟรี MIT, โหลดด้วย script tag เดียวแล้วใช้ได้เลย แต่ไม่มีตาราง และมีหัวข้อแค่ระดับเดียว เหมาะกับ "ข้อความสั้น ๆ ในแต่ละส่วน" มากกว่าบทความยาว
5. **CKEditor 5 และ TinyMCE** หน้าตาเหมือน Word ที่สุด แต่สัญญาอนุญาตเป็น GPL หรือต้องจ่ายเงิน/จำกัด 1,000 ครั้งโหลดต่อเดือน — เสี่ยงทางกฎหมายสำหรับบริษัท จึงไม่แนะนำ
6. **Quill 2** ฟรี แต่ไม่มีการอัปเดตมาเกือบ 2 ปี มีบั๊กภาษาเอเชีย (IME) และปัญหาการเข้าถึง (accessibility) ค้างอยู่หลายรายการ ไม่มีตารางอย่างเป็นทางการ
7. **Toast UI Editor** ถูกปิดโครงการ (archived) แล้ว ใช้ไม่ได้ / **Slate** ต้องใช้ React / **Lexical** ใช้ได้แต่ไม่มีแถบเครื่องมือมาให้ ต้องสร้างเองทั้งหมด / **Milkdown** ออกเป็น Markdown ไม่ใช่ HTML
8. ภาษาไทยไม่ได้ใช้ IME แบบจีน-ญี่ปุ่น จึงปัญหาน้อยกว่า แต่ยังมีความเสี่ยงเรื่องสระ/วรรณยุกต์กับปุ่ม Backspace (พบ issue ค้างใน CKEditor) — ทุกตัวต้องทดสอบพิมพ์ไทยจริงก่อนเลือกขั้นสุดท้าย
9. การวางข้อความจาก Word/Google Docs จะติด "ขยะ" มาด้วย เราต้องมีขั้นล้างสองชั้น: ให้ตัว editor รับเฉพาะรูปแบบที่อนุญาต และก่อนบันทึกล้างซ้ำด้วย DOMPurify พร้อมบังคับหัวข้อให้เป็น H2/H3 เท่านั้น
10. งานถัดไป: ทำหน้าทดลองเล็ก ๆ 1 หน้า โหลด Tiptap จาก jsDelivr แล้วทดสอบ (ก) โหลดได้ไหม (ข) พิมพ์ไทยได้ไหม (ค) วางจาก Word แล้วสะอาดไหม — ก่อนตัดสินใจเขียนโค้ดจริง

## 3. Ranked recommendation (top 3)

### #1 — Tiptap 3 (MIT) — recommended default

**Why:** It is the only candidate that is simultaneously (a) free for commercial use with no key, badge or load quota, (b) officially documented to run from a CDN with `<script type="module">` and no bundler, (c) outputs clean semantic HTML that we can store as-is in `articles.json`/section data, (d) has free extensions for tables, code, YouTube (`nocookie`) and file drop/paste hooks, and (e) enforces brand constraints at the schema level, which is the strongest possible paste defence. It is also the cleanest fit for the **section-based page model**: one small `Editor` instance per text block, each with its own restricted extension list (e.g. a "lead paragraph" block allows only bold/italic/link; an "article body" block allows H2/H3, lists, table, image, callout).

**Integration shape**
- *Loads:* `import { Editor } from 'https://cdn.jsdelivr.net/npm/@tiptap/core@3.31.4/+esm'` and `import StarterKit from 'https://cdn.jsdelivr.net/npm/@tiptap/starter-kit@3.31.4/+esm'` inside one `<script type="module">`. Pin the **same version** on every `@tiptap/*` URL (StarterKit, extension-image, extension-table, extension-youtube, extension-file-handler). Mixed versions or mixing esm.sh with jsDelivr produces the "different instances of a keyed plugin" crash ([#4683](https://github.com/ueberdosis/tiptap/issues/4683)). Prefer jsDelivr `+esm` (the documented path) over esm.sh ([#4873](https://github.com/ueberdosis/tiptap/issues/4873) open). A `<script type="importmap">` can centralise the version string.
- *Toolbar:* ours — a row of `<button>`s calling `editor.chain().focus().toggleBold().run()` etc., styled with the Navy/Soft-Linen tokens and Inter. Tiptap's own UI kit is React-only, so do not plan on it. This is ~150 lines of HTML/JS, and it is what gives us the "restricted toolbar" for free.
- *Output stored:* `editor.getHTML()` string, run through a DOMPurify allow-list (section 5) and written into the section's `html` field (or `articles.json` body). Optionally also keep `editor.getJSON()` for lossless re-editing; HTML alone round-trips fine when the schema is strict.
- *Images:* `FileHandler.configure({ onDrop(editor, files, pos) {...}, onPaste(editor, files) {...} })` plus the toolbar's image button → call our existing upload routine (GitHub commit of the file under `en/posts/img/` or whatever Stage 6 decides) → `editor.chain().insertContentAt(pos, { type:'image', attrs:{ src: './img/x.jpg', alt } }).run()`. Paths stay relative per project rule.
- *Callout / note:* a 20-line custom Node (`name:'callout'`, `group:'block'`, `content:'block+'`, `renderHTML → ['aside', {class:'callout'}, 0]`). Nothing to download.
- *Heading limits:* `StarterKit.configure({ heading: { levels: [2, 3] } })` — H1 is the page title and never editable in-body.

**Caveats to budget for:** write our own paste scrub (the Pro paste handler is paid); test CJK in headings on Safari if any staff type Chinese/Japanese ([#7271](https://github.com/ueberdosis/tiptap/issues/7271)); keep an eye on 3.x minor releases since the version is pinned in HTML.

### #2 — Editor.js (Apache-2.0) — choose if the Admin becomes "blocks all the way down"

**Why:** Native block editor with official Table, Embed (YouTube), Code, Quote, Warning (callout) and Image tools; the Image tool's `uploader.uploadByFile` is exactly "our own upload hook". Output is JSON, which means the public page's HTML is produced by **our** renderer — total brand control and zero paste leakage into the site. The trade-offs: the writing feel is "Notion-like" rather than Word-like; Word tables and nested lists paste as plain paragraphs; keyboard-only/screen-reader experience of the block UI is weaker; and nesting a block editor inside a section-based page gives two competing block systems (page sections vs editor blocks), which confuses non-technical users unless the section model is abandoned in favour of Editor.js blocks entirely.

**Integration shape:** `<script src="https://cdn.jsdelivr.net/npm/@editorjs/editorjs@2.31.7">` plus one script per tool (header, list, table, image, embed, code, quote, warning) — all pinned. `await editor.save()` → JSON stored in the section; a ~120-line `render(json) → HTML` function (also used in a live preview) emits only the tags we allow. Image: `uploader: { uploadByFile: async f => ({ success:1, file:{ url: await ourUpload(f) } }) }`.

### #3 — Trix (MIT) — choose for short text blocks, not full articles

**Why:** The lightest, most "it just works" option: one script tag, a `<trix-editor>` element, consistent HTML out, DOMPurify built in, attachment event for uploads, maintained by 37signals for Rails ActionText. Perfect for the **text-block inside a section** use case (intro paragraph, service description, FAQ answer) where you want bold/italic/link/list/quote and nothing else. **Not** suitable as the full article editor: no tables, a single heading level, no embed node.

**Integration shape:** `<script src="https://cdn.jsdelivr.net/npm/trix@2.1.19/dist/trix.umd.min.js">` + CSS; `<input id="x" type="hidden"><trix-editor input="x">`; read `input.value` (HTML) on save; `document.addEventListener('trix-attachment-add', e => upload(e.attachment.file).then(url => e.attachment.setAttributes({url, href:url})))`. Hide unwanted toolbar buttons with CSS or `Trix.config.toolbar.getDefaultHTML` override.

**Pairing with the section model:** A sensible Stage-6 architecture is **Tiptap everywhere** with two presets ("inline" for section text blocks: bold/italic/link only; "article" for the knowledge-article body: H2/H3, lists, table, image, callout, YouTube, code). Using one library keeps the paste-scrub, toolbar CSS and upload hook in one place. Trix is the fallback if Tiptap's CDN loading proves flaky in the browser test.

On the GPL question specifically: this repository is already public on GitHub, so releasing the Admin page itself under a GPL-compatible licence is *possible*, which would make self-hosted CKEditor/TinyMCE legally usable. But CKEditor's GPL build still shows a vendor badge, both vendors steer commercial users to paid keys, and any future private/premium add-on would re-open the question. The MIT/Apache options remove the issue entirely, so they are preferred.

## 5. Paste-from-Word / Google-Docs sanitising strategy

Two layers, regardless of editor, so that a bad paste can never reach the live site:

1. **Schema as whitelist (in the editor).** Load only the nodes/marks the brand allows. In Tiptap: StarterKit with `heading.levels:[2,3]`, no `TextStyle`/`Color`/`FontFamily`/`Underline` extensions, no `TextAlign`. Anything ProseMirror cannot parse into the schema is dropped automatically, which already kills `<span style="font-family:Calibri">`, `mso-*` styles and `<o:p>` wrappers. In Editor.js the equivalent is loading only approved tools and setting each tool's `sanitize` config; in Trix, `Trix.config` block/text attributes.
2. **`transformPastedHTML` pre-pass (Tiptap/ProseMirror).** Before parsing, run the clipboard HTML through: strip `<!--[if ...]>` conditional comments; remove `<style>`, `<xml>`, `<meta>`, `<link>`; unwrap `<span>` and `<font>`; convert `<b>`/`<i>` to `<strong>`/`<em>`; demote `<h1>` → `<h2>`, `<h4>`–`<h6>` → `<h3>` (or paragraph); convert Word's "MsoListParagraph" paragraphs with leading `•`/`1.` into real `<ul>/<ol>` (the hardest part — Tiptap's paid Paste Handler and CKEditor's free Paste-from-Office do this; our free version can be ~60 lines handling bullets and simple numbering, accepting imperfect nesting); replace Google Docs' `<b style="font-weight:normal">` wrapper (Docs wraps everything in it) with its children; collapse `&nbsp;` runs to spaces.
3. **Images in pasted content.** Word pastes `<img src="file:///...">` or `data:` URIs; Google Docs pastes `googleusercontent` URLs. Policy: drop any `<img>` whose `src` is not a relative `./` path, and show a toast "Images must be uploaded with the image button". Optionally intercept `data:` images in `onPaste`, upload them through our hook, and re-insert with the relative URL.
4. **Final gate before save (DOMPurify from CDN, MIT).** `DOMPurify.sanitize(html, { ALLOWED_TAGS: ['p','h2','h3','strong','em','a','ul','ol','li','blockquote','aside','table','thead','tbody','tr','th','td','img','figure','figcaption','pre','code','iframe','br'], ALLOWED_ATTR: ['href','src','alt','title','class','colspan','rowspan','allow','allowfullscreen','loading'], ALLOW_DATA_ATTR:false })` with a hook that only permits `iframe src` matching `https://www.youtube-nocookie.com/embed/` and `a href` starting with `https://`, `mailto:`, `./` or `../`. Links to external sites get `rel="noopener"`.
5. **Plain-text paste shortcut.** Teach the owner `Ctrl/Cmd+Shift+V`; it is the most reliable "clean paste" and Tiptap honours it natively.
6. **Preview with site CSS.** Render the sanitised HTML inside the real `theme.css` in the Admin preview so stray formatting is visible before publishing. Because colours/fonts come from the theme, not from the editor output, the brand is enforced at render time even if a stray class survives.

## 6. Open questions

1. **Live CDN test (blocking).** This sandbox could not reach jsDelivr/esm.sh. Before Stage 6: open a single HTML file in Chrome, Safari and Firefox that imports `@tiptap/core`, `@tiptap/starter-kit`, `extension-image`, `extension-table`, `extension-youtube`, `extension-file-handler` from `cdn.jsdelivr.net/npm/...@3.31.4/+esm` and confirm no "keyed plugin" error and that `getHTML()` works. Also time the first load on a normal office connection.
2. **Thai typing test.** Type a paragraph with stacked vowels/tone marks (e.g. "กี่ ปั๊ม ใต้ ที่สุด") on Windows (Kedmanee) and macOS; test Backspace behaviour after a tone mark, selection across clusters, and Shift+Arrow. CKEditor has an open bug exactly here; Tiptap/ProseMirror must be verified by hand because no issue exists either way.
3. **Where do uploaded images go?** The Admin is static; uploads must become commits to `en/posts/img/` (GitHub API with a PAT in the owner's browser) or a drag-to-folder manual step. This decides whether the editor's upload hook is synchronous (local preview) or returns a final relative URL.
4. **Stored format for sections.** HTML only, or HTML + Tiptap JSON side by side? JSON guarantees lossless re-editing of custom nodes (callouts) after future schema changes; HTML alone is simpler and matches the existing `article-loader.js` approach.
5. **Full-article vs block editor decision.** If the knowledge articles stay long-form, Tiptap "article" preset is right. If the team wants Notion-style pages built from reusable sections, revisit Editor.js so there is only one block model.
6. **Pro features.** Is a Tiptap Pro subscription (paste handler, drag handle, UI) worth paying for later, or do we stay fully free? Not needed for Stage 6.
7. **Bundle size confirmation.** Replace the "≈" estimates with real numbers from the browser Network tab during the test in Q1.
8. **Accessibility bar.** Decide the minimum: keyboard-operable toolbar with `aria-pressed`, visible focus, and `aria-label`s is achievable in our own toolbar in a day; a formal VPAT is only available from CKEditor/TinyMCE.
